# Android: оплата верификации через Google Play

Этот документ описывает серверную часть покупки значка верификации на Android.
Мобильное приложение уже использует тот же сценарий, что и на iOS: цена приходит
из магазина, а название и описание продукта — из API Wawat.

## 1. Идентификаторы

| Поле | Значение |
|---|---|
| Android package name | `az.buking.buking` |
| Google Play product ID | `wawat.app.verification` |
| Purchase option ID | `buy` |
| Тип товара | One-time product / Buy |
| Базовая цена | `0.99 USD` |

Все значения должны совпадать посимвольно. Другой product ID создавать нельзя.

## 2. Каталог Wawat

Авторизованный запрос `GET /api/v1/purchases/catalog` должен возвращать активный
товар:

```json
{
  "product_id": "wawat.app.verification",
  "kind": "verification",
  "name": "Локализованное название",
  "description": "Локализованное описание"
}
```

Название и описание локализуются API по `Accept-Language`. Цену для Google Play
в этот ответ добавлять не нужно: приложение показывает локальную цену из
`ProductDetails`, полученного непосредственно от Google Play.

## 3. Проверка покупки

Клиент отправляет:

```http
POST /api/v1/verification/pay
Authorization: Bearer <user-token>
Content-Type: application/json
```

```json
{
  "method": "google",
  "purchase_token": "<google-play-purchase-token>"
}
```

Backend обязан через Google Play Android Developer API проверить:

1. package name равен `az.buking.buking`;
2. product ID равен `wawat.app.verification`;
3. покупка действительно оплачена и не отменена/возвращена;
4. токен ранее не был применён к другому пользователю или товару;
5. покупка относится к текущему Google Play приложению.

После успешной проверки в одной транзакции БД:

1. сохранить покупку и Google order ID;
2. активировать значок верификации пользователя;
3. сделать обработку идемпотентной по платформе и purchase token/order ID;
4. при повторе того же запроса вернуть прежний успешный результат без повторной
   активации или списания.

Успешный ответ:

```json
{
  "data": {
    "activated": true,
    "status": "paid",
    "is_verified": true
  }
}
```

Клиент принимает успех по `activated: true` или `status: "paid"`.

## 4. Google Cloud и Play Console

В GCP-проекте `wawatair-b212f` должен быть включён сервис:

```text
androidpublisher.googleapis.com
```

Service account:

```text
firebase-adminsdk-fbsvc@wawatair-b212f.iam.gserviceaccount.com
```

должен быть добавлен именно в тот Play Console developer account, где находится
Wawat Air, и иметь для приложения права:

- View app information;
- View financial data, orders, and cancellation survey responses.

JSON-ключ хранить только в защищённой конфигурации сервера. Не добавлять его в
репозиторий и не передавать в открытом чате.

## 5. Ошибки

- `422` — токен невалиден, товар/package не совпадает или покупка отменена;
- `401/403` от Google — неверный service account или недостаточно прав;
- `503` — Google verification временно недоступна;
- при любой ошибке валидации не активировать значок и не помечать покупку
  обработанной.

Сообщение пользователю должно быть локализованным. Сырые ответы Google и секреты
не возвращать в мобильное приложение.

## 6. Синхронизация профиля

После успешной оплаты следующие запросы должны сразу возвращать обновлённое
состояние:

- `GET /api/v1/verification` — статус оплаты/верификации;
- endpoint текущего профиля — `is_verified: true` и данные значка.

Кэш пользователя и статуса верификации нужно сбросить сразу после активации,
чтобы приложение не требовало выхода со страницы или повторного входа.

## 7. Проверка перед запуском

1. Убедиться, что `wawat.app.verification` активен в Google Play для всех нужных
   регионов и доступен внутреннему тестовому треку.
2. Проверить, что каталог API содержит `kind: verification`.
3. Сделать покупку тестовым аккаунтом из установленной через Play сборки.
4. Убедиться, что backend вернул HTTP 200 и значок появился сразу.
5. Повторить тот же purchase token и убедиться, что ответ снова успешный, но
   вторая запись/активация не создаётся.
6. Проверить отмену покупки и отказ Google: значок не должен активироваться.

Новый сертификат приложения для этого товара не нужен. Для Android требуется
активный Google Play product и серверная проверка purchase token; подпись AAB
остаётся существующей Play App Signing подписью приложения.
