# Продвижение только для active / moderation — задача бэкенду

> **Статус: бэкенд готов и в проде** (commit 803855e). Отличие от ТЗ: код ошибки
> `LISTING_NOT_PROMOTABLE` (UPPER_SNAKE, как все коды API). Клиент код не
> сравнивает, показывает `message`, поэтому правок не понадобилось.
> `listing.status` теперь есть во всех ответах продвижений, включая
> `/me/promotions`. Ниже — исходное ТЗ, оставлено для истории.

Сейчас сервер принимает заказ VIP / boost / продления на объявление в **любом**
статусе: настройка `allow_purchase_in_moderation=true` отключает существующую
проверку целиком. Нужно вернуть проверку на сервер.

## Правило

Продвижение (новый заказ VIP или boost, продление, повторная покупка) разрешено,
только если у объявления `status` = **`active`** или **`moderation`**.

Во всех остальных статусах — отказ: `partially_booked`, `fully_booked`, `paused`,
`expired`, `rejected`, `deleted`.

`allow_purchase_in_moderation` не должна выключать проверку. Максимум она решает,
входит ли `moderation` в список разрешённых (сейчас должна входить).

## Где проверять

| Эндпоинт | Что делать |
| --- | --- |
| `POST /listings/{id}/promotions` (создание заказа) | 422, если статус не разрешён |
| `POST /promotions/{id}/extend` (продление / повторная покупка) | 422 по статусу объявления этого продвижения |
| `POST /promotions/{id}/quote` | `applicable: false`, `reason: "listing_not_active"` (такой reason клиент уже понимает) |
| `POST /promotions/{id}/pay`, `method: "card"` | 422 **до** создания оплаты картой: заказ могли создать, пока объявление было активным |
| `POST /promotions/{id}/pay`, `method: "apple"` / `"google"` | **НЕ отказывать.** Деньги магазин уже списал. Чек принять и активировать как сейчас, иначе человек заплатит и ничего не получит |

Для заказа через App Store / Google Play клиент сначала вызывает создание или
продление, и только потом открывает окно оплаты. Поэтому отказ на создании и
продлении останавливает человека до оплаты. Этого достаточно.

## Формат ошибки

HTTP **422**:

```json
{
  "message": "Bu elanı hazırda irəli çəkmək olmur. Promosyon yalnız aktiv və ya yoxlamada olan elanlar üçündür.",
  "code": "listing_not_promotable"
}
```

`message` — на языке пользователя. Клиент показывает его как есть. Текст взять из
ключа CMS `promotion.listing_not_promotable` (клиент уже использует этот ключ).
Нужно добавить его в CMS на az / ru / en / tr / uk.

## Желательно (не блокирует)

В `GET /me/promotions` в объект `listing` добавить `status` объявления:

```json
"listing": { "id": "…", "type": "trip", "city_from": "…", "city_to": "…", "status": "expired" }
```

Клиент уже читает это поле. Без него приложение отдельно запрашивает
`/listings/my`, чтобы решить, показывать ли кнопки «Uzat» / «Yenilə».

## Проверка

- `active`, `moderation` → создание, продление, оплата картой проходят, как сейчас.
- `expired`, `paused`, `rejected`, `fully_booked`, `partially_booked` → создание и продление = 422 `listing_not_promotable`.
- Заказ создан на активном объявлении, объявление истекло, потом `pay` картой → 422, деньги не списаны.
- То же, но `pay` с чеком Apple / Google → чек принят, ошибки нет.
- `deleted` → 404 или 422, но заказ не создаётся.
